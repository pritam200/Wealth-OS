# Technical Gap Matrix

Systems-level counterpart to [`PRODUCT_GAPS.md`](PRODUCT_GAPS.md). "Current" is verified against
the code; "Industry Pattern" is sourced from [`COMPETITIVE_RESEARCH.md`](COMPETITIVE_RESEARCH.md).

**"Proposed Architecture" is a recommendation, not a decision.** Per the spec's ordering
(RESEARCH → AUDIT → BENCHMARK → **DESIGN** → IMPLEMENT), these feed the design docs under
`docs/architecture/` and are not yet committed to.

---

## 1. Document & ingestion layer

| System | Current | Problem | Industry Pattern | Proposed Architecture |
|---|---|---|---|---|
| **Document abstraction** | No generic `Document` entity. Only `PendingPdf`. **18 parsers, each with independent logic** | Adding an issuer means a new parser class; no shared lifecycle, status, provenance or retry. Nothing enumerates "all documents in flight" | Classify → route → extract, with the document as a first-class entity carrying `(doc_type, issuer, confidence)` | `FinancialDocument` root entity with the **10 spec'd statuses**; parsers become `DocumentExtractor` strategies registered against `(issuer, doc_type)`; `PendingPdf` becomes a projection |
| **Classification** | `canParse(from, subject)` polled across 18 parsers | O(n) predicate scan; no confidence; no fallback ordering; adding a parser can silently shadow another | **Cheap cascade:** sender domain + DKIM → subject regex → attachment MIME/producer → first-page fingerprint → model **last**. Jupiter's published query is stages 1–2 only | Ordered `ClassificationStage` chain returning `(type, issuer, confidence, matchedStage)`; model invoked only when earlier stages abstain |
| **Extraction confidence** | Flat **0.85 gate** on model-reported confidence | **Research shows logprobs give only 0.705 ROC AUC** on DocILE — "a frontier LLM confidently transcribing OCR noise produces high log-probabilities for a wrong answer" | **Multi-signal:** cross-field arithmetic validation, deterministic-parser/LLM agreement, self-consistency across passes, grounding checks | `ConfidenceVector { arithmetic, parserAgreement, selfConsistency, grounding }` with an explicit combination rule; **calibrate the threshold against a real sample before go-live**, don't pick 0.85 by feel |
| **Traceability** | Values trace to an *email*, not a *span* | **"EVERY FINANCIAL NUMBER MUST BE TRACEABLE" is not satisfied by email-level provenance** | **Mandatory verbatim source spans**, mechanically verified to exist in the source text. Buys hallucination defence and user-facing provenance in one move | Every extracted field carries `{value, sourceSpan, page, bbox?}`; extraction **fails** if the span isn't found in the source. Non-negotiable |
| **CAS parsing** | Generic PDF path | Reinventing a solved format; CAS is high-volume and structured | `casparser` (MIT) parses CAMS + KFintech + NSDL/CDSL eCAS to typed models | Dedicated CAS extractor (port or shell out); **reserve the LLM pipeline for the long tail** |
| **PDF passwords** | `SavedPdfPassword` + `PendingPdf` retry | One global strategy | Per-issuer rules: **CAS = PAN for all types except KFintech** (user-defined); HDFC = Customer ID; ICICI = DOB/PAN fragments; SBI netbanking = account no. but YONO = DOB | `PasswordCandidateProvider` per issuer, tried in order, user-prompt on exhaustion. **Never a deterministic generator for user-facing secrets** — that constraint is separate and absolute |
| **OCR** | Not gated | — | Gate on text-layer presence: chars-per-page below threshold → OCR | Rare path for Indian statements (overwhelmingly text-layer + ruled tables) |

## 2. Identity, dedup & reconciliation

| System | Current | Problem | Industry Pattern | Proposed Architecture |
|---|---|---|---|---|
| **Ingest identity** | `TransactionFingerprinter` — SHA-256 over financial content, **correctly excluding Gmail message id** so forwards collide | Good, but single-granularity: no notion of row-within-document | Stripe: compare params to original, error on mismatch, **cache results including errors**. TigerBeetle: transfer id *is* the idempotency key | Extend to `SHA-256(gmail_message_id ‖ attachment_hash ‖ row_index)` at the **document** layer, keeping the existing content fingerprint at the **economic** layer. Two hashes, two purposes |
| **Economic identity** | Content hash only | **Same trade via contract-note PDF and broker email has different bytes — the hash cannot match them.** This is the central dedup gap | Composite natural key with tolerance: `(account, instrument, direction, quantity, amount ± ε, date ± N days)`. **Where a strong external reference exists — UTR, ISO 20022 `EndToEndId`, RRN — prefer it and skip fuzzy matching entirely** | `FinancialEventIdentity` with a **three-tier resolver**: exact external reference → composite key + tolerance → fuzzy with score. **Harvest UTR/RRN aggressively — it is the highest-value field on the page** and turns fuzzy matching into exact |
| **Restatement** | Not modelled — a corrected document would be a new row or a conflict | No way to express "the same event, restated" | **Plaid:** `pending_transaction_id` links the posted row to its pending version; pending appears in `removed`, posted in `added`. And Plaid **admits matching sometimes fails** | `supersedes_id` link on the event; **never overwrite** — append the restatement and link it. **Design the failure path explicitly**, because matching will sometimes fail |
| **Reconciliation** | `ReconciliationService.checkAll` — **3 of ~17** checks; binary pass/fail | No exception typing, no partial matches, no investigation payload | **matched / unmatched / partially-matched / exceptions**, typed by cause (timing difference, amount variance, unidentified). Banding ≥95 auto / 85–94 auto+flag / 70–84 human / <70 distinct | `ReconciliationCheck` registry (17+ checks); `ReconciliationException` with `type`, `score`, and the source rows needed to investigate. Also adopt **matching (pre-commit, blocking) vs reconciliation (post-commit, comparative)** as distinct controls |
| **Ledger invariant** | ✅ **Intact** — `Holding.quantity`/`averageCost` written only at `PortfolioService.java:258-259` | The invariant is enforced by convention, not by a test | — | **Add an ArchUnit/reflection test that fails the build if a second writer appears.** This is our strongest asset and it is currently undefended |
| **Event sourcing** | CRUD + ledger replay | Replay is already event-sourcing-shaped for holdings | Double-entry "turns tampering into an arithmetic alarm." **But** Azure: projections become effectively immutable — *"even a simple bug fix can cause a butterfly effect as it runs against every transaction since the beginning of time"* | **Follow the published pragmatic guidance: event-source the ledger only; keep CRUD elsewhere.** Do **not** convert the whole system |

## 3. Scoring engine

| System | Current | Problem | Industry Pattern | Proposed Architecture |
|---|---|---|---|---|
| **Factor composite** | `AnalystService.java:142` — `tech×0.30 + mom×0.20 + val×0.20 + sent×0.30` | **No quality factor. No growth factor. 30% on sentiment, which VR doesn't use for rating at all.** Structurally misspecified | VR: Quality 25 / Growth 20 / **Valuation 35** / Momentum 20 | 9 spec'd dimensions built on **rank → z-score → average within bucket → equal-weight buckets** |
| **Weighting method** | Fixed hand-chosen weights | Arbitrary, undocumented provenance | AQR, MSCI, S&P all converge on equal-weight buckets, explicitly **rejecting** optimisation: *"a potential nightmare of choices and dimensionality… We choose the latter"* | **Fixed equal-weight buckets. Do NOT use PCA, Gram-Schmidt or covariance-optimised weights** — measured evidence: **HML–RMW and RMW–CMA flip sign** between 1963–99 and 2000–26. The covariance matrix you estimate is not the one you live with |
| **Multicollinearity** | RSI/CCI/Stochastic/ROC/MACD-line pairwise **ρ>0.9**, naively averaged → momentum **~4:1 over-weighted** | Silent mis-weighting; the composite doesn't measure what it claims | Measured: **HML–CMA 0.68** is what makes HML redundant in FF5. **RMW/CMA/UMD are the near-orthogonal trio** (0.02, 0.05, −0.02) | Collapse each family to **one** representative, then blend across near-orthogonal axes. **Measured payoff: HML+CMA (ρ=0.68) → Sharpe 0.41, zero gain; HML+UMD (ρ=−0.19) → 0.67, nearly double** |
| **Double-counted accruals** | N/A (not yet built) | **A trap to avoid:** accruals appear independently in Piotroski (CFO>ROA), Beneish (TATA) and QMJ (ACC) | — | **Assign accruals exactly one slot.** Same class of error as the momentum over-weighting |
| **Quality factor** | Absent | The single biggest scoring gap | **MSCI: exactly 3 descriptors** — ROE, D/E, 5y earnings variability; winsorise 5/95 → z-score → **negate D/E and variability** → average; **exclude the security entirely if ROE is missing.** AQR QMJ is the 4-bucket deep version | **Start with MSCI's three** (cheapest defensible quality factor in existence), plus **Novy-Marx GP/A = (REVT−COGS)/AT** — *"the cleanest accounting measure of true economic profitability"* |
| **Sector handling** | One formula for all stocks | **Wrong for banks/NBFCs** | **VR and Simply Wall St independently** maintain a separate ratio set for financials: ROA, NIM, provision coverage, CAR, SGR gap; **PE → PE-to-SGR** | `SectorScoringProfile` strategy, selected by sector. Two independent sources converging makes this non-optional |
| **Rating eligibility** | Scores everything | Produces a confident number on unratable stocks | VR's 5 published exclusions | `RatingEligibility` gate returning `INELIGIBLE(reason)` — a first-class outcome, not a null |
| **Red flags** | Not modelled | — | Tickertape scores them as a **separate channel**; Zerodha Nudge fires pre-trade. **Both treat them as disqualifiers, not score contributions** | `RedFlag` channel with **veto** semantics. A pledged, ASM-listed stock should not be rescued by a good valuation score |
| **Valuation bands** | Not modelled | — | Morningstar: 5-star discount **20/30/40/50/75%** scaling with uncertainty, seeded from TTM daily return SD | **Borrowable free — it needs only price volatility.** Drive our uncertainty tier off measurable data quality (bars available, parser confidence, history length) |
| **Percentile normalisation** | N/A | **Look-ahead risk** | Asness et al.: naive backtests embed look-ahead because *"you didn't know the 10y mean in real time"* | **Expanding window, never full-sample.** Any percentile must use only data available at that date |
| **Regime overlay** | None | — | **Faber 10-month SMA**: compound 9.32%→10.18%, max DD 83.7%→42.2%. **Daniel-Moskowitz panic state**: WML beta falls 0.518 (t=−28.4), Sharpe 0.682→1.194 OOS | **200DMA/10-month market filter only.** Regime-modulating a *stock-level* signal is supported **only for momentum** — Cederburg et al. (72 of 103 strategies lose) is direct evidence against generalising |
| **Rejected inputs** | Sentiment at 30% | — | Fed model/BEER: E/P alone adj. R² 29.6% vs **1.4%** for E/P−Y | **Drop sentiment from the rating.** Never use BEER as a score input. Drop forward P/E and PEG — the data isn't obtainable free |

## 4. Card engine

| System | Current | Problem | Industry Pattern | Proposed Architecture |
|---|---|---|---|---|
| **Reward model** | `CardRewardRule` + `SpendAggregator`; rate × spend | **Stateless.** Cannot express "caps exhausted but ₹40k short of a fee waiver" | **The correct answer is `argmax` of marginal value** = capped rate + Δ(milestone) + Δ(fee waiver) − surcharge | `MarginalValueEngine` over live counters. **Build the counters first; the rate table is the easy part** |
| **Counters** | `monthlyCapAmount` field, **no counter entity** | Four state dimensions on four clocks; **SBI uses statement cycle, HDFC uses calendar month** | — | `UtilizationCounter(userCard, capOrMilestone, windowStart, windowEnd, consumed, source: DERIVED\|USER_CONFIRMED)` |
| **Exclusions** | **Zero exclusion files** | **The most common modelling error is one exclusion list per card.** Kotak publishes **five lists for five purposes**, with per-variant carve-outs, and says it "is not exhaustive" | — | `EligibleSpendSet` keyed by **purpose** (REWARD / MILESTONE / FEE_WAIVER / SPECIFIC_BENEFIT) with card-variant overrides |
| **Rule versioning** | None | **Devaluations arrive with 30–60 days' notice.** Kotak's own PDF carries an "effective 1 Apr 2026" clause. Backtesting requires "what was true last March?" | FinArt stamps a per-card "verified on" date | **Effective dating on every rule, plus `supersedes_id`.** Non-negotiable |
| **Provenance** | None | Where issuers don't publish MCC maps, **we are inferring** — FinArt chose category-level modelling for exactly this reason | — | `source_url, source_type(MITC\|TNC_PDF\|PRODUCT_PAGE\|COMMUNITY), verified_on, confidence(HIGH\|MED\|LOW)` on every rule/cap/milestone row. **The SBI Cashback cap disagreement across three sources is the whole argument for this** |
| **UPI/RuPay route** | Not modelled | **Recommending a Visa card for a UPI rail is a correctness bug** | Only RuPay on UPI; P2P/C2C/P2PM/ATM/IPO/MF blocked; acquirer blocks 6010–6013, 6011, 6051, 6211, 4829, 7322, 74xx, 78xx/7995/9406 | `RouteEligibility(card, route, allowed, blockedMccs[], blockedTxnTypes[], perTxnLimit, dailyLimit, interchangeFloor, smallMerchantExempt)` |
| **Reward uncertainty** | Point estimate | **Whether a ₹5,000 UPI payment earns anything can depend on the merchant's turnover band — unobservable to the user and to us** | NPCI parity mandate exempts issuers earning no interchange | **Model as a confidence band, not a number** |
| **Point valuation** | Single rate | Axis runs **two currencies with a ~5× gap** (EDGE Points ₹0.20 vs EDGE Miles ~₹1+) | Best-case transfer value as headline is *"the single biggest source of inflated claims"* | `value_per_point` **vector by redemption route** with `{rate, liquidity, minRedemption, expiry, transferRatio}`. Headline = user's **declared** behaviour; show conservative / realistic / ceiling |
| **Category inference** | Merchant-name inferred, honestly `inferred=true` | Lower precision than MCC | FinArt deliberately chose category-level "because issuers rarely publish the exact MCC map" | **Keep the honesty flag.** MCC where obtainable, category otherwise — and say which was used |

## 5. Data acquisition

| System | Current | Problem | Industry Pattern | Proposed Architecture |
|---|---|---|---|---|
| **AMFI NAV** | Fixed — binds by header name, 16MB codec buffer | Depends on following a 302 from `www.amfiindia.com` | **Feed moved to `portal.amfiindia.com/spages/NAVAll.txt`; header now carries new `Plan`/`Option` columns that break positional parsers** | Point at `portal.` directly. **Our header-name binding already survives the column change — this is the fix validating itself** |
| **Price history** | Existing market-data service | — | **Dhan: free with account, daily back to inception.** Kite: ₹500/mo for the same. Upstox: daily only 1 year — weak | **Dhan primary, Kite backup.** Independent check against `nsearchives` bhavcopy |
| **NSE access** | — | **`www.nseindia.com` is Akamai-fenced and blocks datacenter IPs outright; cookie-priming does not help** | `nsearchives.nseindia.com` is **open** — bhavcopies, equity master, index constituents, corp-action archives | **Archives from the server; JSON APIs only from a residential IP.** Use `jugaad-data` (maintained) not `nsepy` (dead since 2020) |
| **Fundamentals** | None | No free structured source; building an XBRL ingestor across ~5,000 listed cos is a multi-month project | **Screener.in HTML: 12 years annual + quarterly + ratios + shareholding, unauthenticated 200, and `/company/<SYM>/` is not disallowed by robots.txt** | Polite scrape (1 req/2–3s), cache aggressively, re-scrape only post-results. **Find the live ToS before any redistribution — `/terms/` 404'd. Personal use plausibly fine; republishing is not** |
| **Filings** | None | — | `api.bseindia.com` returns 200 JSON, **no datacenter-IP block**, needs only a UA + Referer | BSE for announcements and scrip master; NSE archives for corp actions |
| **MF holdings** | None | **No central machine-readable source.** Per-AMC XLSX, inconsistent headers, WAFs, JS-gated pages | SEBI mandates monthly disclosure within 10 days (debt: fortnightly within 5) | **First-class subsystem, not a feature.** 3–6 weeks + 1–3 days/month. ISIN as join key. **Top-40 truncation (Zerodha's approach) is a legitimate v1 if disclosed** |
| **Analyst estimates** | None | — | **No free source exists.** Refinitiv/Bloomberg/CapIQ = ₹lakhs to $20–30k/yr | **Scope out.** Trailing/TTM + historical 3/5/10y CAGR. A PEG on *historical* growth is defensible **if labelled honestly** |
| **User MF holdings** | CAS + Gmail | — | **AMFI directed MF Central to stop sharing investor data with third-party apps (Sept 2025)**; AA gates on regulatory status | **CAS-first is now the only viable architecture — and it is what we already have.** No change needed; the moat just got deeper |

## 6. Cross-cutting

| System | Current | Problem | Industry Pattern | Proposed Architecture |
|---|---|---|---|---|
| **Data sufficiency** | Ad-hoc (`NOT_SIZED`) | Each subsystem invents its own "can't answer" | VR's 5 exclusions; Zerodha suppressing XIRR; Simply Wall St's auto-fail on <10y dividend history | First-class `Insufficient(reason, whatWouldFixIt)` result type used by **every** computed number |
| **Explainability** | `Factor` list with notes | Weighted z-scores are hard to explain | **Simply Wall St: 6 binary pass/fail checks per axis.** "Failed 4 of 6 health checks, here they are" **is** a reason | Binary checks as the explanation layer over the continuous score. Directly serves "EVERY RECOMMENDATION MUST HAVE A REASON" |
| **PII in LLM calls** | Sanitisation required by standing constraint | — | Jupiter/CRED/INDmoney all scope-limit; CheQ holds CASA certification | Keep the sanitiser on the path to **any** fallback provider; `AiAuditService` redaction already covers secrets |
| **Rate limiting / politeness** | — | Scraping Screener and 40+ AMC sites | — | Central `PoliteFetcher` with per-host rate limits, caching and a real UA. **A 403 from an AMC is a scheduling problem, not an error to retry hard** |
